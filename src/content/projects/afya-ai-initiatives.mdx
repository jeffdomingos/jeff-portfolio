        ## Contexto e Descoberta

        No ecossistema corporativo da Afya, principal hub de educação médica e software de saúde do Brasil, a integração de ferramentas de inteligência artificial em produtos B2B tornou-se uma diretriz estratégica central. Como Senior Product Designer, fui responsável por explorar e estabelecer fluxos de trabalho viáveis de IA para ideação, testes de usuários e handoff para os desenvolvedores.

        Dentro da plataforma enterprise RX PRO — que conecta a indústria farmacêutica diretamente aos médicos — identificamos uma lacuna crítica de negócios: uma parcela significativa de médicos recebia caixas de amostras físicas, mas não recebia visitas presenciais dos representantes de vendas.
        
        Para resolver isso, projetei um **Representante Digital via IA (MVP com Parceiro Farmacêutico)** oferecendo uma "Cobertura Virtual" contínua e baseada em evidências. Embora tenha nascido como uma iniciativa customizada para o contexto específico dessa farmacêutica (piloto inicial com **100 a 200 médicos**), a solução foi priorizada na esteira de produto pelo seu alto potencial de escalabilidade: transformar uma demanda sob medida em uma funcionalidade nativa e um novo módulo de oferta enterprise dentro do ecossistema RX PRO para atender múltiplos laboratórios. Estruturalmente, a experiência foi projetada para funcionar como um drawer contextual (slide-over) no portal web RX PRO e como uma thread conversacional dedicada no WhatsApp, alinhando-se perfeitamente ao nosso Design System principal.
        
        Trabalhando ao lado da gestão de produto, um desafio chave de UX foi definir o que significava o sucesso para um agente de IA. Indo além de simples logs técnicos de infraestrutura, ajudei a estruturar um framework de métricas: focando em Ativação, Qualidade de AI (Taxas de Fallback e Transferência), Negócios e, principalmente, o **Engajamento Qualificado** (sessões com mais de 3 interações ou aprofundamentos clínicos).

        ## A Solução: Stack de Prototipagem Rápida

        Com as ferramentas de IA evoluindo rapidamente, construí intencionalmente um pipeline de prototipagem em múltiplas etapas para avaliar a melhor forma de gerar ativos de design e lógicas interativas até o handoff final.

        ### Estágio 1: Protótipo Interativo NLU (Lovable)
        Para testar fluxos conversacionais dinâmicos sem construir um backend completo, iniciei utilizando o **Lovable** para criar um protótipo web interativo em React/TypeScript, espelhando a interface do RX PRO. Isso permitiu validar rapidamente 5 estados conversacionais cruciais: NLU imediato sem botões forçados (compreensão de intenções em texto livre), sugestões clínicas rápidas via *UI chips*, interação baseada em RAG (citando fontes de bulas), fluxos de transferência para humano (escalation) e tratamento humanizado para o "unhappy path" de entregas não recebidas.

        ### Estágio 3: Handoff para Engenharia e LangChain
        Atuando em Design Engineering com **VS Code + GitHub Copilot**, liderei a integração do código frontend:

        * **Aceleração de Ciclo (de 6 semanas para 1.5 semana):** No fluxo tradicional, passar da ideação ao código rodando em ambiente de testes levaria de 6 a 8 semanas (múltiplas sprints de handoff no Figma, abertura de tarefas no Jira, implementação de UI e refatoração de gargalos de experiência no QA). O time de engenharia aproveitou a maior parte dos componentes React diretamente na esteira de produção, precisando apenas integrar os serviços finais sem ter que construir a interface do zero a partir do Figma.

        ## The Solution: Rapid Prototyping Stack

        Because AI tools were rapidly evolving, I deliberately built a multi-stage prototyping pipeline to evaluate how design assets, interactive logic, and code generation could best serve our team from early discovery to final handoff.

        ### Stage 1: NLU-First Interactive Prototype (Lovable)
        To test dynamic conversational flows without building a full backend, I started with **Lovable** to construct an interactive React/TypeScript web prototype mirroring the RX PRO UI. This allowed us to quickly validate 5 key conversational states: immediate NLU without forced buttons (understanding intent from free text), quick clinical suggestions via UI chips, RAG-grounded interaction (citing monograph sources), human escalation flows, and empathetic unhappy path handling for non-delivered samples.

        ### Stage 3: Code Migration & LangChain Handoff
        Stepping into a Design Engineering role with **VS Code + GitHub Copilot**, I led the frontend code integration:

        * **Cycle-Time Reduction (from 6 weeks to 1.5 weeks):** In a traditional design-to-dev workflow, moving from ideation to test-environment code typically takes 6 to 8 weeks (across multiple Figma handoff sprints, Jira ticketing, dev builds, and fixing static UI edge cases during QA).         * **Initial Handoff (OpenAI Chat Kit):** Engineering initially selected OpenAI's Chat Kit starter template (a suite of pre-built UI components for chat interfaces). Engineering reused the majority of our React components directly in production, requiring only backend integration rather than building the UI from scratch from Figma.
